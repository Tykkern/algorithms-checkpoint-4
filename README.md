# Контрольная точка 4: стек, поиск в ширину, алгоритм Флойда

Практикум по алгоритмам. Шесть задач, решения на Java.

| № | Задача | Класс | Подход | Время | Память |
|---|---|---|---|---|---|
| 1 | Ожидание более высокой цены | `PriceWait` | монотонный стек | O(n) | O(n) |
| 2 | Кратчайший путь на карте | `GridPath` | поиск в ширину | O(n·m) | O(n·m) |
| 3 | Повторное посещение узла | `CycleDetector` | Флойд, два указателя | O(n) | O(1) |
| 4 | Наибольший прямоугольник из единиц | `MaxRectangle` | гистограммы + монотонный стек | O(n·m) | O(m) |
| 5 | Лабиринт с ключами и дверями | `KeysMaze` | BFS по состояниям (клетка, ключи) | O(n·m·2^k) | O(n·m·2^k) |
| 6 | Повторяющееся число | `DuplicateFinder` | Флойд, вход в цикл | O(n) | O(1) |

k в задаче 5 это число типов ключей, не больше 10.

## Запуск

Нужен JDK 17 или новее, Gradle скачается сам через wrapper.

```
gradlew test                          # тесты
gradlew run -q --args="2" < input.txt # задача 2, ввод из файла
```

Номер задачи передаётся аргументом, входные данные читаются из stdin в формате
из задания, ответ печатается в stdout. Например, для задачи 5:

```
3 3
S.a
#A#
.T.
```

ответ `5`: сначала за ключом `a`, потом обратно и через дверь `A`.

На Windows проект лучше держать в папке без кириллицы в пути. Иначе Gradle
не находит тестовые классы (`ClassNotFoundException`), хотя они скомпилированы.

## 1. Через сколько дней цена станет выше

Монотонный стек индексов. В нём лежат дни, для которых более высокая цена ещё не
встретилась. Очередной день снимает со стека все дни с ценой строго ниже своей
и записывает им ответ `текущий день - их день`, потом сам кладётся в стек.
Поэтому цены в стеке сверху вниз не убывают. Кто остался в стеке в конце, так
и не дождался, ответ 0.

Каждый день один раз кладётся и не больше одного раза снимается, итого O(n).
Перебор «для каждого дня искать вперёд» дал бы O(n²), на убывающих ценах
это 2 * 10^10 шагов.

## 2. Кратчайший путь на карте

Поиск в ширину из `S`. Все ходы стоят 1, поэтому клетки выходят из очереди
в порядке расстояния, и первое попадание в клетку уже кратчайшее. Клетка
кодируется числом `row * m + col`, очередь и расстояния лежат в обычных массивах
длины `n * m`, без объектов на каждую клетку. При карте 1000 на 1000 это
два массива по миллиону `int`.

## 3. Повторное посещение узла

Нужна память O(1), поэтому массив посещённых не подходит. Используется алгоритм
Флойда: из `start` идут два указателя, медленный на 1 шаг, быстрый на 2. Если
путь заканчивается (`-1`), быстрый дойдёт до конца первым, и ответ `NO`. Если
путь зацикливается, оба окажутся в цикле, и быстрый догонит медленный, потому что
расстояние между ними по циклу уменьшается на 1 за шаг. Встреча означает `YES`.

Узлы нумеруются с 1, значение меньше 1 считается отсутствием продолжения.
Петля на себя (`next[i] = i`) тоже повторное посещение.

## 4. Наибольший прямоугольник из единиц

У любого прямоугольника из единиц есть нижняя строка. Для каждой строки считаем
высоты столбиков из единиц, которые заканчиваются в ней: `heights[c]` растёт на 1
на единице и обнуляется на нуле. Получается гистограмма, и остаётся найти в ней
наибольший прямоугольник.

Гистограмма решается монотонным стеком: в стеке индексы с возрастающей высотой.
Когда приходит столбик не выше вершины, для снимаемого столбика известны обе
границы, за которые его высота не продолжается: справа текущий индекс, слева
новая вершина стека. Это его наибольший прямоугольник. В конце добавляется
столбик высоты 0, чтобы снять всё оставшееся. Итого O(m) на строку и O(n·m) на всё.

## 5. Лабиринт с ключами и дверями

Обычный BFS по клеткам не работает: в одну и ту же клетку бывает нужно вернуться
уже с ключом (как в примере выше). Поэтому состояние это пара
(клетка, набор собранных ключей), и посещёнными отмечаются пары. Набор ключей
`a..j` хранится в 10 битах, вариантов 1024. Дверь пропускает, только если бит
её ключа стоит, ключ добавляется при входе в его клетку.

Состояний не больше 900 * 1024, около 920 тысяч, каждое обрабатывается один раз.
Задачу 2 тем же кодом решать нельзя: при карте в миллион клеток и 1024 масках
состояний было бы в 1024 раза больше.

## 6. Повторяющееся число

Массив читается как граф: из индекса `i` стрелка ведёт в `nums[i]`. Индексов
`n + 1`, значения от 1 до `n`, поэтому в индекс 0 не входит ни одна стрелка, и путь
из 0 рано или поздно зацикливается. В первый узел цикла входят две стрелки, одна
из хвоста и одна из цикла, то есть два разных индекса с одним значением. Это
и есть повтор.

Вход в цикл ищется алгоритмом Флойда. Медленный и быстрый указатели встречаются
внутри цикла. Затем один возвращается в 0, и оба идут по одному шагу: встретятся
они ровно на входе в цикл. Массив не меняется, хранятся только два индекса.

Другой вариант с памятью O(1) это бинарный поиск по значению с подсчётом чисел
не больше середины, но он работает за O(n log n).

## Тесты

- на каждую задачу граничные случаи и сверка с переборным решением на случайных
  входах (для задачи 2 сверка с решением задачи 5 на картах без ключей);
- входы максимального размера из ограничений с таймаутом 5 секунд;
- `MainTest` проверяет чтение ввода и формат вывода для всех шести задач.
